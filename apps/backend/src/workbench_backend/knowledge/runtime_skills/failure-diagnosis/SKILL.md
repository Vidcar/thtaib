---
name: failure-diagnosis
description: Investigate a reproducible bug, failed tool, regression or repeated unsuccessful fix using evidence before editing. Skip ordinary successful work and generic factual questions.
---

Capture the exact failing input, outcome and relevant state without retaining secrets. Separate invalid arguments, missing capability, denied access, tool failure, application failure and unknown external effects.

Reproduce through the smallest relevant selected route. Form an explanation that evidence could disprove; locate the earliest incorrect transition before changing the responsible owner. Browser, desktop, shell and source readers are alternatives chosen for the failing domain.

Reread current state before retrying an uncertain mutation: a timeout or failed acknowledgement does not prove that nothing happened. Verify the targeted repair against the original failure and a meaningful regression. Read references/outcomes.md when recovery is involved.
