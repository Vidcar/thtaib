---
name: verify-delivery
description: Verify a meaningful implementation, bug fix or requested release and report concrete evidence separately from claims and incomplete checks. Skip trivial replies that make no delivery claim.
---

Choose checks by affected behavior and its consumers. Review existing evidence with read tools, or run deterministic checks through authorized execution. Add real backend/model or visible UI checks when the requested outcome depends on them.

Confirm the observed application uses the intended build and process identity. Inspect the output artifact or live behavior. Report passed, failed, skipped and unavailable checks separately, with relevant limits. A scripted model is mechanism evidence; a build is not a passed UI test.

Read references/evidence.md for completion rules. Do not create a competing verification process or start unrelated runtimes for a small text change. Use the project's established checks, when present.
