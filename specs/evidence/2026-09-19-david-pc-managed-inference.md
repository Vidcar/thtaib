Seen working live on the target platform with the preferred capability UAT model, all as executable observations at the HTTP boundary: managed pin → download → start → health → smoke → stop with owned process identity and the exact profile argv (MOD-004 managed clause); startup and per-request bags applied and visible in the launched argv and the outbound body (MOD-003, MOD-005 settings clause, ARCH-003); bundle reuse and read-only GGUF inspection (MOD-001 reuse clause, MOD-002); Chat → Deep Agents harness → real tool call → file in the project (AGT-001 project-bound half, STATE-002); the follow-up turn resuming the same thread with prior tool messages on the wire (STATE-001); the captured request agreeing with the effective setup (AGT-002); token trust 401/403 (API-003).

**Not covered**, so no row is `verified`: import with companion files and Hugging Face import (MOD-001); a deliberately unsupported value and cross-surface comparison (MOD-003); the connected-endpoint half of MOD-004 (seen only on the Linux manual run); multimodal input and compaction (MOD-005); project-less Chat (AGT-001, [DEV-003](../deviations.md#dev-003)); capture after compaction (AGT-002); a history edit leaving files untouched (STATE-002). Also not exercised: cold-start load, CUDA OOM, `mlock`/`no_mmap` rejection, cancel mid-generation, restart-reconcile of a live server, the Electron window, vision, MTP, long context, multi-slot concurrency.

Product observations for follow-up (not failures): the create-with-`auto_start` health wait is about 2 s, so real models return `unhealthy` until polled; `llama-server` stdout/stderr are discarded; the pin re-downloads unconditionally (292 s); the model runs in thinking mode by default and no reasoning control exists in the per-request keys; the `stream` per-request key is dead; no Deep Agents scratch files landed in the project for this short run.
