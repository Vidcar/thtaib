# Proposal

## Why

Engineering guidance and validation are scattered, and a passing check can be mistaken for evidence of a complete user outcome. Give coding agents a small repository-local workflow and prove it on one existing model-control path before any broader stabilisation.

## What Changes

- Replace the repository entry point with concise routing and preserved project protections.
- Add four portable development skills and a thin local verification command over existing checks.
- Exercise failure propagation, honest evidence, fresh-context skill selection and portability.
- Close one confirmed model-control outcome or recovery gap with a regression and a disposable negative control.

## Capabilities

No new or modified product requirements. This tooling change uses `skip_specs: true`; the pilot enforces existing outcome and state-ownership contracts.

## Impact

Repository agent instructions, development-only skills, scripts and existing tests; at most one narrow product fix. No runtime skill registration, global Codex configuration, GitHub CI, new dependencies, product-surface renaming or repository-wide refactor.
