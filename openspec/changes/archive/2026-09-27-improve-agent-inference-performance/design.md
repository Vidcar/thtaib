# Design

## Context

See proposal.md for motivation. Baseline evidence is in `.scratch/prompt-cache-diagnosis-20260927-1790504944/diagnosis.json`. Forty real requests on the selected Qwen 27B deployment confirmed outline cache invalidation; image removal caused a small suffix rewind, not a reproduced full reset. New screenshot prefill dominated visual latency. Adapter aggregation consumed about three seconds across 4,656 chunks of a large file write; public SSE remained about 17 ms behind upstream output.

## Decisions

- Keep the initial outline immutable in each compiled run, including its inclusion decision. Label snapshot age; tools already append authoritative changes. Rebuild on a new run rather than mutating early system instructions mid-loop.
- Use canonical capture references already stored on tool messages to reconstruct visual messages after their original complete tool-result batches. Hydrate bytes only for the outbound request. Include the same projection in native compaction counting, and let upstream compaction remove older capture references. Do not invent a parallel conversation store or retention engine.
- Perform matching setup capability preparation before compilation/first main inference for authorized capture runs. Retain the existing private probes and setup fingerprint, fallback and capability refresh. Cached checks remain harmless when called by capture handlers.
- Collect only tool-call fragments and finish metadata for adapter validation, join once at completion and reuse strict validation. Native framework accumulation continues to own its full response.
- Extend the existing latest-value telemetry publisher with bounded completed samples (64). Add nullable reported prefill seconds and locally observed first substantive delta delay; keep decode duration semantics. Merge history at model/end boundaries and project it independently from transcript tokens.
- Benchmark f16 versus q8 KV and supported batching/MTP settings with the actual weights, context size, text/tool/vision fixtures and GPU memory. Apply a winning saved configuration through the normal manager, preserving 98,304 context unless a materially different decision is required. No runtime replacement or weight download.

## Risks / Trade-offs

- Retaining visual context costs context space → count it in native compaction and preserve bounded image transport; remove references only through deliberate compaction.
- Initial outline can become stale → name it as the run-start snapshot and use exact tool/read results for current facts.
- Quantized KV can affect capability → compare correctness as well as latency; retain the baseline if no safe measured improvement exists.
- Runtime settings require reload → benchmark in isolated product data, coordinate GPU use and restore owned state on failure.

## Migration Plan

Keep optional measurement fields compatible with absent observations. Run focused regressions and live before/after tests, then the required delivery gates. Deliver through a normal PR/merge, refresh the established local application, and apply only the measured winning runtime settings. Rollback uses the preceding source revision and recorded original saved startup values; weights and unrelated data remain intact.

## Verified Delivery Evidence

- Actual application validation passed three isolated scenarios on the original saved Qwen setup: declaration edit, screenshot followed by another tool, and an exact large streamed file write. After the declaration edit, the system prefix remained unchanged and prefill processed 29 tokens with 5,183 cached in 0.383 seconds; the diagnosis baseline processed 5,370 tokens in 42.215 seconds. Each run built its outline once. Evidence: `.scratch/prompt-cache-validation-20260927-1790508664/validation.json` and adjacent request timings.
- The first visual run completed all six private capability requests before work inference. The screenshot's exact retained bytes remained at the same historical position across the later tool call; 9,157 tokens were cached and 101 newly processed afterward. Prefill and first-output timing survived per-call boundaries, and the exact streamed write completed without adapter response aggregation.
- Runtime comparison completed 41 requests across eight tested configurations/repeats with text, cached continuation, streamed-tool, vision and decoding fixtures passing. The measured winner uses q8_0 K/V cache, ubatch 1024, batch 2048 and two draft-MTP tokens, retaining 98,304 context. Repeated cold 4,049-token prefill improved from 32.495 to 3.185 seconds, long decoding from 28.43 to 77.93 tokens/second, and observed shared GPU memory from 3.16 to 0.59 GiB. Evidence: `.scratch/runtime-tuning-20260927/summary.json` and `recommendation.json`. These bounded fixtures do not establish general model-quality equivalence.
- The winning startup values were saved through canonical configuration/reconfigure operations to the existing configuration (revision 5), preserving deployment, weights, projector, request sampling and 98,304 context. Normal image and tool-image checks passed. Tuned actual-application validation then passed all four cases, including canvas-only colours/shapes/positions and exact text recognition. The same 22,399-byte screenshot required 9.192 seconds of prefill versus 33.333 seconds with the original runtime; the following tool retained 9,128 cached tokens and processed 103 in 0.196 seconds. The exact large write decoded 4,637 tokens at 75.31 tokens/second versus 4,641 at 27.94 originally. Matching capability evidence was reused without probes in the next visual run. Source settings, preset, original processes and model residency remained unchanged during validation. Evidence: `.scratch/applied-agent-performance-tuning/after.json` and `.scratch/prompt-cache-validation-20260927-1790510677/validation.json`.
- Local gates passed: backend default 942 tests with one skip, integration 200, generated-contract freshness and desktop build. Mounted native Chat checks additionally passed narrow large-text timing/history geometry, missing values, hover/focus/touch, keyboard expansion/scroll access and Escape dismissal. No raw prompts or image bytes are included in these change notes.
- Normal desktop shortcut recovery refreshed the idle backend and reloaded the existing desktop instance, preserving the router, loaded model, configuration, saved chats and their empty composers. A disposable real-model run through the refreshed everyday service completed its read/edit/read task and retained four timing observations; after the edit it reused 1,233 tokens, processed 30 in 0.133 seconds and observed first output after 0.156 seconds. The disposable chat and owned records were removed through the normal lifecycle API. Evidence: `.scratch/agent-performance-local-refresh/after.json`. Independent stream review found 19–31 ms public-output lag during the large tuned write; cumulative publication work overlaps model generation and does not establish a sustained stream bottleneck.
