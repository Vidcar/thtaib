# Design

## Context

See [proposal.md](proposal.md) for motivation and scope. Inspection found an integrated `WorkbenchSidebar`, six Chat rail pages, browser auto-opening, a model picker that already starts exact managed configurations, and native markdown/tool rendering with existing chronology and scroll guarantees. Much of the presentation should reuse those mechanisms.

The substantive gaps are in ownership. `MAIN_AGENT_FIELDS` currently excludes main-model and tool choices; the setup editor follows that boundary. Knowledge choices currently store exact version references, while the agreed product behaviour follows the latest saved records on a new submission. Existing queue admission, execution snapshots, reconfiguration protections and backend readiness must remain authoritative.

Hugging Face inspection already knows exact file membership, shards, disk sizes, immutable revisions and publisher recipes. Models already exposes context, KV precision and GPU/fit controls. Hardware detection currently confirms NVIDIA presence rather than providing memory telemetry; KV placement is not yet a canonical application setting. The estimator is an addition to this boundary, not proof of existing fit support.

## Goals / Non-Goals

**Goals:** keep one configuration resolver and durable admission path; preserve exact accepted work while making the next draft configurable; make the everyday surfaces compact with progressive disclosure; map import choices to the configuration actually saved and loaded.

**Non-goals:** change the execution harness, introduce a second runtime or storage catalogue, implement Workflows/Lab, deliver speech or image engines, turn slash commands into direct tool execution, or make hardware estimates admission gates. Existing deferred destinations/routes and recovery remain available under their current contracts.

## Decisions

### 1. Separate rail, chat list and contextual dock

Refactor the existing shell rather than add another application. Keep a slim persistent destination rail, with Search and Notifications icons at the top and Settings at the bottom. The separately collapsible/resizable project/chat list belongs to Chat; other destinations use their own existing list/editor space. Search opens the existing retained-history search, rather than quietly adding a universal search backend. Preserve global New chat versus project `+`, archive filtering, project identity, attention navigation and initial-load recovery.

The right dock has only Files, Browser and Helpers. Keep its remembered open/tab/width choice and reading state. Opening requires a person choosing the toggle, a tab or a file/helper link; activity only updates a small indicator. Remove browser auto-open. Combine project tree, selected chat uploads/outputs and authorized reusable saved copies in Files using existing record origins and preview libraries. Global Library remains the bulk catalogue. Export/delete move to header `⋯`; retry/edit stay by their owning messages, with effect disclosure preserved.

Use existing theme/density/control tokens. Start with a roughly 52–56px rail and bounded chat-list width, not fixed screenshot coordinates. At narrow widths collapse secondary columns before compromising transcript/composer; never overlay the dock. These are reversible layout defaults. Integrated navigation was rejected because the separate rail remains usable when the chat list is hidden.

### 2. One compact composer and shared pickers

Keep this order inside the composer: `+`, access, Plan only while enabled, model, adjacent sliders icon, agent, context/speed, Send/Stop. The circular action is Send while idle and Stop for the whole live turn, including tool execution, waiting and finalization; it does not change with individual token streams. Enter queues during active work, Shift+Enter inserts a newline, and cancellation pauses the queue. Preserve IME and pending-admission protection. Hover/focus describes the action and changes appearance without adding standing instructions.

`+` contains attachments, Add context, Skills & actions and Plan. Reuse the same searchable picker through mouse selection and `@`/`/` autocomplete. `@` adds authorized references; `/` selects a saved skill or a registered task shortcut using currently enabled tools. Selection creates removable chips and never executes until Send/Queue. Slash selections are consumed only after that input is accepted, retained on failure, and frozen onto that message. A highlighted suggestion consumes Enter; Escape dismisses it; normal Enter behaviour resumes once the picker closes.

Avoid an ever-growing menu and avoid raw tool-call commands. Supporting resources retain native skill semantics; browsing a skill must not eagerly put its full body into model context.

### 3. Split draft intent from accepted execution

The backend owns three distinguishable facts: editable next-message intent, the immutable resolved snapshot of each accepted input, and observed loaded runtime state. The frontend may show a draft candidate but cannot make it execution authority.

At submission/admission, atomically resolve the selected current agent record and latest saved selected skill/memory/protected-instruction records into exact versions, model/configuration identity, overrides, tools, context, mode and policy. Persist that snapshot with the accepted input before queueing. Resolve record identity, not a frontend-cached `current_version_id`, and retain deselection/empty-tools semantics. Unsaved edits do not participate. Existing queued items, resumed interrupts and running helpers retain frozen choices. Explicit queue-item edits are a new deliberate revision, not a selector side effect; backend revision checks reject races.

Serialize authored capture in Knowledge → Application → Model configuration lock order, including queued setup revisions. Knowledge saves already consult application scope; existing application-held setup reads consult the model store, so reversing either order can deadlock. Keep those locks limited to resolution and snapshot persistence, outside model loading and execution. Text-only queue edits retain authored versions and settings; an explicit setup edit resolves and freezes the latest saved records again. Synchronize the accepted-input identity with the deliberate queue revision so an obsolete retry conflicts and an identical revised retry reuses that revision's snapshot.

Recheck live permissions, resource availability and compatibility at dispatch/resume without refreshing frozen authored content. Shared admission chooses the existing owned deployment or loads the exact requested configuration safely. A queued startup override must not edit a saved configuration or a launch still used by an earlier item. Retain the current reconfiguration protections for named active/queued/waiting/helper/Lab consumers.

While active, model/agent/tuning changes alter draft intent only. Use at most a small changed-state dot or short label when the distinction matters; no standing 'for next message' paragraph. Load/reload at the staged message's safe admission boundary. When idle, explicit model/configuration or fixed-model agent selection loads immediately; selecting the exact healthy binding does nothing. Opening/restoring a chat stays cold. Failed idle selection retains its previous binding; staged load failure preserves the exact queued candidate and recovery, pauses progression, and never substitutes a model or duplicates submission.

Locking all selectors during a reply was rejected because the user wants to prepare follow-ups. Immediate active reload was rejected because it could change accepted work. Freezing at dispatch alone was rejected because saved edits would otherwise alter already queued messages.

### 4. Clarify model and agent ownership

Agents own role/instructions, enabled tool groups and individual tools, connections required by those tools, knowledge defaults and named helpers. Their default model mode is Use Chat model; optionally they bind a specific saved model/configuration. Choosing a fixed-model agent intentionally selects that model, with safe staging above; an inherited-model agent leaves the chat model alone. Keep the independent Chat selection as the inherited choice so returning to an inherited-model agent restores it. While a fixed-model agent is selected, the model picker reflects that binding and provides a short route to change the assignment in Agents; it must not silently override it.

Chat owns access, Plan/Work mode, live Windows grants, project/session identity and optional knowledge/context additions. Project supplies its folder/knowledge, never model or execution authority. Agent tools remain intersected with current chat grants/mode and helper limits. Tools stay out of both the composer agent dropdown and `+`; missing tool dependencies route to Agents, Connections or the corresponding live grant control. Browser lifecycle/takeover belongs in Browser; Windows target/grant controls belong under Chat access; installations/connections belong in Settings.

Guided new-agent creation uses Role/instructions → Model/tools/knowledge → Review/save, then the existing list/grouped editor. Keep helpers and advanced requirements discoverable without repeating them in Chat. Preserve immutable saved versions and inspectable historical run ownership.

### 5. Per-model Chat tuning, permanent defaults in Models

Use one small sliders-triggered editor containing supported Thinking/effort and context with one Apply. Retain actual supported choices and unknown/unsupported facts; returned reasoning visibility is separate. Store chat-local overrides keyed by canonical bundle/model identity, with selected configuration identity recorded separately and revalidated on switching. First use seeds saved defaults, returning to a model restores its chat-local changes. Changing the saved base configuration preserves explicit chat overrides and exposes conflicts rather than silently resetting them. Connected models use their existing stable endpoint identity; context reload is offered only with real owned authority.

Apply commits the chat candidate once and invokes safe reload only for startup changes. Preserve draft, attachments, history and reading position. Keep response length and thinking-token-limit editing in Models; their actual enforcement and usage evidence remain unchanged. Expandable details may expose provenance, but not duplicate those controls in Chat.

Balanced/Deep presets remain explicit choices; update the existing MOD-017 rule that seeded Balanced automatically so it cannot overwrite selected model defaults. Native context accounting, output reservation and summarization ownership stay unchanged.

Only a fresh bundle without a valid saved default is seeded with a `Default` configuration inheriting publisher/template/native response defaults. Existing authored configurations remain intact. Retained-history validation before a context reload checks message/media/tool structure through the existing compatibility owner. Observed capacity and the one native Deep Agents summarizer then govern the next dispatch: reducible history is compacted; an irreducible request fails actionably with canonical checkpoint history retained. A context decrease is not refused merely because history exists, and preview estimates do not establish fit.

The model picker has one bounded searchable row per model; only models with multiple configurations have an expand affordance. Expansion never loads. Status dots derive from the exact selected configuration and observed health: green ready, amber loading/waiting, red attention, grey idle. Accessible hover/focus names carry the same facts. Existing saved configurations alone cannot establish residency.

### 6. Preserve native transcript behaviour while changing presentation

Keep `AgentMessageFeed` and its upstream interaction identity/markdown path. Change surface styling to small right-aligned user bubbles and assistant text flowing on the background. Keep markdown, code, tables, diffs, image/file links, tool owners, parent/helper isolation and warm/reopened chronology. Details remain collapsed by default and individually expandable; errors, approvals and questions stay actionable. One generic status remains at the composer. Measurements update independently without rebuilding the transcript, moving selection or scroll. Reuse existing follow-at-bottom behaviour, not a new scroll manager.

### 7. Guided knowledge with lossless native source

Retain the searchable Skills/Memories/Instructions list/editor. Default skill editing shows Name, When to use, Instructions and supporting files. A Source tab edits the native SKILL.md. Both views edit one draft; parse validation identifies source that guided fields cannot represent, preserves unknown frontmatter/metadata and resources, and never destructively rewrites an imported package. Native slugs/uniqueness still validate. Save produces an immutable version; the next submission resolves it according to decision 3. Keep memory policies/proposals and protected-instruction authority intact; group operational settings under their existing Settings owners when tidying screens.

Use the backend's native parser for read-only preview and lossless edits to known frontmatter scalars; do not approximate YAML validation in the renderer. Distinguish valid native source from source representable by Guided: unsupported mappings remain intact and editable in Source, and valid native Source may still be saved. Pending or failed guided transformations retain the local fields and prevent saving an outdated source. Skill names are unique among active records within the same scope and scope identity, including disabled records. Supporting files can be added, replaced or removed in the draft; explicit Save creates one immutable source/resources version while earlier resources remain inspectable. Reuse existing safe path, link, binary, file-count and size constraints. Draft file selection never executes scripts or installs dependencies.

### 8. Guided import and advisory hardware estimate

Keep the existing importer/job owner and publisher recipe path; reorganize its UI into Find, Choose and Review/download with Back preserving the exact choices. Re-entering the unchanged inspected source from Find retains the selected file/projector, context, KV and recipe choices without reinspection; selecting a different source inspects it and resets source-dependent choices. Direct file URLs remain exact selections. Choose shows complete quant file size, detected total/available GPU and RAM, supported KV precision/location and the context slider. Detail shows weights, KV cache, runtime/compute overhead and assumptions, plus an approximate context marker and GPU/RAM placement. Distinguish weights/layers in RAM from KV cache in RAM. Review carries the selected values into the initial saved configuration alongside existing immutable revision/projector/text-only/recipe choices. Do not clear an explicit context/KV choice while creating recipe configurations.

Extend backend hardware observation and GGUF inspection through the existing model boundary with a bounded estimate contract: source identity, observation time, selected parameters, byte breakdown/ranges, assumptions and unsupported/unknown reasons. Before download, use verified repository information and bounded GGUF metadata reads where available; avoid fetching full weights or guessing architecture from a filename. After install, prefer actual GGUF metadata and native llama.cpp memory/fit observations. Hybrid, sliding-window, MoE/MLA, multimodal and multi-GPU layouts require honest ranges or unavailable components when the model cannot be accurately projected. Per-device memory is not automatically one pooled GPU.

The linked calculator illustrates density and interaction, not an authoritative formula. Its simplified layer/cache assumptions must not become a second runtime fit implementation. Verify supported KV-placement flags and units against the pinned runtime source, add them to canonical descriptors/validation/launch mapping, and report requested versus applied values. Distinguish user-selected CPU KV placement from automatic weight-layer offloading.

No save/download/load button is disabled for an estimated shortage. Do not silently change context, KV precision or placement to make the estimate fit. Unknown hardware stays usable. Actual runtime failure identifies the attempted settings and preserves them for adjustment. Compare alternatives without applying them automatically.

The estimate contract separates selected startup, hypothetical evaluated startup, source identity/time, per-device hardware facts, file/weights/cache/compute bytes, assumptions and explicit unknowns. Before import, only recognized dense `llama`, `qwen2` and `qwen3` scalar layouts receive a cache calculation, using installed GGUF quantization block sizes. Sliding-window, hybrid/recurrent, MoE/MLA, variable layer layouts and vision allocations stay unknown where unsupported. The context marker is a qualified upper bound for one freshly observed GPU, assumes all weights/cache on that device, and excludes unknown compute/driver overhead; it is not a verified fit. Explicit positive layer counts require native tensor placement and do not supply metadata-only GPU/RAM weight placement or a context marker. CPU KV uses canonical `kv_offload: false` / `--no-kv-offload` independently of weight-layer offloading.

Repository listings and successful/failed metadata inspections cache at immutable revision/file identity (32 entries). Range inspection is capped across selected shards at 16 MiB, 16 requests, 1 MiB prefixes and a 15-second deadline; each request caps its connect/read/other transport timeouts to the remaining shared deadline, with 3-second connect and 5-second read ceilings. Unsupported ranges fail before consuming the body; prefixes may include initial tensor bytes in small files. Explicit Refresh retries metadata failures. Hardware observation uses per-GPU UUID/name/total/free memory and RAM, a 2-second telemetry timeout, 5-second cache and visibly stale previous facts after observation failure; stale GPU budgets do not supply a context marker. UI edits debounce remote requests by 250ms and installed native predictions by 500ms, with stale response ownership/abort guards.

Installed estimates independently attempt the pinned `b11045` sibling `llama-fit-params` helper even if bounded metadata inspection is incomplete. Its `--fit-print on` path predicts without loading tensor data or allocating model tensors; backend/driver initialization is possible. Requested local `-m` and supported cache/context/layer/batch/parallel options are passed through the canonical mapper. The helper defaults to one sequence while server Auto selects its own slot count: unless parallel is explicit, evaluated startup records `parallel: 1`, marks server slot allocation unresolved and suppresses the native Auto context marker. Its rows therefore do not establish full server memory or an exact launch match. Native Auto fitting may first return hypothetical context/layers, then the print path evaluates that candidate, while saved/requested settings remain unchanged. Prediction has one worker, a shared 15-second deadline and 256 KiB output cap; its 30-second/32-entry cache keys runtime identity, file size/hash record/mtime and evaluated settings, retaining the original calculation time on reuse. Device rows remain separate; unsupported native multi-device/tensor remapping is unavailable, and projector, draft and driver allocations remain qualified unknowns. Actual loaded process RAM and launch observations are shown separately from prediction.

Import defaults are Automatic context, f16 K/V and GPU KV. Back retains exact choices; explicit Download writes a job-owned initial configuration before recipe cloning. A stable namespace keyed by the original import job keeps imported recipe configurations distinct from earlier configurations, inherits that job's startup and preserves user edits on recovery/retry. Normal repeated model-card creation still reuses its existing editable recipe identities. This private identity mechanism does not add another storage authority.

Native validation on the installed Qwen3.5 4B hybrid bundle, with context 4096/all GPU weight layers/CPU KV, completed the no-allocation helper in about 1.4 seconds and returned separate CUDA/Host model/context/compute MiB rows. The real estimator boundary preserved those requested settings and reported the bundle's excluded projector allocation; this is prediction evidence, not a model-load or capability claim. Native load and cross-screen acceptance use the isolated preview root and reused weight paths, never copied/downloaded weights or everyday backend changes.

Subsequent isolated native validation imported the existing 4B primary weight by reference, delivered `--no-kv-offload` to an owned child with observed context 4096 and four automatic server slots, and completed a real native model request. It then restored the healthy GPU-KV/context-8192 configuration for integrated Chat validation. Default process logging did not expose actual cache allocation bytes, so these remain unobserved; the native predictor's separate CUDA/Host context rows evaluated one sequence and do not establish that server's full allocation. Live bounded inspection also retained the exact pinned Hugging Face primary link, recovered selected file/tensor bytes and correctly left hybrid cache/compute projection unknown before import. These technical checks do not imply Dave's UX acceptance.

After seeing the native compact rail, small user bubbles and open assistant answers, Dave's early layout feedback was: “Keep this direction; assess it in everyday use.” This accepts the direction for continued implementation and defers everyday-use assessment; it is not acceptance of every completed surface.

The continuously mounted isolated Windows desktop then completed real model turns with an `echo` tool, an answered `ask_user` wait, a different queued 4K agent/helper setup while an 8K turn was active, restart and queue continuation. The helper's `task` and `echo` results retained their identity; a newly answered question settled the actual `ask_user` outcome. The transcript, draft and selection survived a warm navigation and Electron reopen. Stopping an active list-update run retained a visible partial result and offered continuation; stopping an `ask_user` wait settled its pending tool outcome. At 100% and 125% native Electron scale factors, the half-width rail, collapsed chat list and explicitly opened Files/Browser/Helpers dock remained usable, as did Models, Agents, Knowledge and Settings; both themes were inspected at 100%. Keyboard picker selection and chip removal were exercised natively, with IME and additional keyboard paths covered by mounted desktop regressions. The isolated browser worker was unavailable, so its actionable install path was checked but a live browser session was not claimed. A 2.43 GB remote import was inspected through Review/Back without starting a transfer. No actual KV allocation measurement or everyday-workspace data change is claimed.

### 9. Minimal copy with accessible detail

Across Chat, Models, Agents, Knowledge and Settings use short names, recognizable controls and change indicators. Put supporting detail on hover, keyboard focus or expansion. Reserve persistent messages for actionable errors, approvals, unknown estimates and meaningful unavailable state. A staged selector needs an indicator only when it differs from current work; routine use does not need repeated 'next message' prose. Accessibility and meaningful effect disclosures remain available; compactness must not hide uncertainty or grant scope.

## Risks / Trade-offs

- Latest-version resolution can race Save → resolve atomically at admission, preserve exact version IDs and reject missing/deleted records without silently dropping them.
- Shared models and queues can deadlock or change each other's launch → reuse shared admission; test same/different startup selections across active turns, helpers and queued work; never mutate a frozen launch in place.
- New rail/list/dock columns can crowd half-screen Chat → collapse secondary columns and test actual Windows scaling, keyboard and long labels; preserve drafts/read position.
- Estimates can imply precision they do not have → show approximation and freshness, test supported architecture calculations, make unknown components explicit and retain native observed fit as authority.
- Source/guided transitions can lose imported skill metadata → round-trip native packages and supporting files, including unrecognized frontmatter and invalid source.
- Presentation changes can regress mounted streams → test multi-turn live rendering, tool transitions, delayed metadata, queue handoff, cancellation and reopen, not just screenshots.

## Migration Plan

Deliver in coherent slices: first ownership/snapshots, then basic rail/composer for early native review, then full Chat controls/panels/transcript, guided Agents/Knowledge, model import/estimator, and final cross-screen wording/validation. Mark tasks against implemented behaviour and observed checks.

Store new intentions in the existing application records and contracts, with existing permission/launch identities preserved. This development project does not need compatibility shims for obsolete synthetic data. Preserve weights and unrelated work; avoid deleting user data as part of a layout change. Retained historical runs use their exact snapshots. If a referenced record cannot resolve, give its established recovery path rather than creating a hidden replacement agent/model.

Run focused backend/default/integration, desktop build, shared-contract freshness when changed, OpenSpec and whitespace checks. Validate live Windows interactions with isolated `.scratch/` product data. Review the basic layout before accumulating remaining controls, then review major Agents/Knowledge/Models surfaces. Record technical results and Dave's UX acceptance separately here or in the delivery PR. Preview images are not acceptance of the built product.

Rollback reverts affected application/spec changes without deleting weights or historical snapshots. Reconcile touched main requirements with the current versions at implementation/archive time; preserve unrelated `startup-catalogue`, `lab-workbench` and `consolidate-product-contract` work.
