# Design

## Context

See proposal.md for the authorized outcome. Source-level reproductions confirm F01/F02/F03/F04/F07 in current main 21136f3; F05/F10 describe intentional exact-grant and virtual-resource boundaries. Existing native graph execution, checkpointer, CompositeBackend routes, asset storage, process trees and connection adapters are the integration owners.

## Goals / Non-Goals

**Goals:** finish verified report items and useful extensions through existing owners, with source/result identity and truthful permissions, plus a complete item-level resolutions report and reproducible local evidence.

**Non-Goals:** replacement agent loops, generic call-any-tool dispatch, remote CI, automatic permission/configuration changes, arbitrary script-loading authority or unmeasured cache claims. The report's later semantic-navigation recommendation is an evaluation against existing selected integrations; no bespoke language-server/index implementation is authorized by a measured need in this audit.

## Decisions

- Preserve executable schemas rather than recursively stripping dictionary keys. A small application overlay supplies descriptions/aliases/effect hints without replacing upstream validation.
- Keep deterministic lexical discovery, five-item batches and new-turn reset; bind continuation to query and accepted selection/version. Trust built-in public-web identity at every Plan projection, never names or external annotations alone.
- Retain bounded acquired UTF-8 text in existing large-tool-results storage before previewing. Add one range/literal-search reader only because line-only native reads cannot recover arbitrarily long single lines; reader authority remains owner-bound.
- Keep exact saved grants unchanged. Add explicit project-write grant records with concrete path scope/exclusions and live checks; no shell classifier, deletion inheritance or read-permission reinterpretation.
- Native deletion remains the upstream operation and requires an opt-in profile/filter change plus project/subtree validation. One custom structured edit composes exact-original replacements into one validated atomic file replacement; it does not replace edit_file or introduce competing dialects.
- Extend owned process handling for jobs and immutable skill resources. Script resources materialize into hash/version-bound owned directories, use existing shell authority/approvals and do not write executables into unrelated projects.
- Bundle instruction/reference runtime skills independently from repository engineering skills. Templates create reviewable drafts, preserve model settings and never invent connection/Knowledge IDs or transfer Chat-owned grants into Agent records.
- Root writes shared planning/report/contracts serially; independent implementers own contract/discovery, evidence/UI tools, and permissions/runtime skill surfaces. Fresh-context review receives raw diff and validation evidence.

## Risks / Trade-offs

- New authorization paths can widen scope accidentally → negative tests for traversal, junctions, excluded paths, revoked grants, helper narrowing, Plan and tools-off.
- Evidence may exceed acquisition budgets → report actual bytes/coverage and retain a useful tail without claiming unacquired data is complete.
- Local-model/tool-worker behavior differs from mocks → run real Windows processes/browser/desktop and fixed-model disclosure/skill exercises; capture exact build/model identity and measured results.
- Native file mutations and retained routes may overlap → preserve native same-batch guard, add structured-operation conflict checks and keep result routes read-only.

## Migration Plan

Add optional typed grant fields/kinds without changing saved exact rows. New tools/skills/presets require explicit selection; existing accepted snapshots retain their authored values. Run relevant backend/default+integration, desktop build, generated contracts and spec gates, independent review and isolated native/model validation before merge. Refresh the established local build only after verification, preserving weights, chats, drafts and settings. Update handover and item-level report at milestones and delivery.
