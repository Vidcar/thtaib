## Goals / Non-Goals

Repair supported current defects at the existing authority/observation boundaries. Preserve accepted identities, frozen settings, uncertainty and live permission checks. No new feature work, speculative cleanup, dependency upgrade, duplicate queue/agent loop or arbitrary file splitting. Later Lab/workflow changes and the lean engineering workflow remain unchanged. No speed claim without equivalent measured workload evidence.

## Decisions

| Confirmed finding and reachable path | Owner and smallest remedy | Acceptance boundary |
| --- | --- | --- |
| Idle Chat Send reaches interaction start; project-busy admission persists a queue item but the bridge dereferences no run or returns an older run. Retry with a new identity can duplicate later work. | Chat admission remains authority; use protocol optional run identity, acknowledge exact queued identity, wake existing coordinator, and reconcile the exact accepted queue in Chat. | Actual HTTP interaction command, empty/prior-run chats, lost response, identical retry, later dispatch once, mounted composer ownership. |
| Stop on a queued-only input leaves a pending cancellation with no future worker to settle it. | Settle under the existing conversation admission lock when no admission is in flight; retain the cancellation tombstone. | Queued stop/removal, held admission, restart and unchanged project owner. |
| Lab capture releases a project reservation after the normal queue wake has drained, leaving accepted Chat work idle. | Signal the existing coordinator after actual reservation release and outside its lock. | Barrier-controlled capture/release or failure, eventual queue progress without manual dispatch, no wake loop. |
| Desktop control dispatch times out or changes identity, then its adapter turns `desktop_effect_uncertain` into ordinary `ToolException`. | Preserve the existing typed harness error through tool adaptation and existing durable uncertainty gates. | Actual tool and middleware, persisted outcome, inspection requirement, pre-dispatch refusal control, no repeated dispatch. |
| Saved configuration changes while Chat remains mounted leave residency/Thinking/context previews keyed to old data. Its own accepted choice can also invalidate the picker completion guard. | Include saved revision in preview identity; distinguish completion of the accepted selection from unrelated owner changes. | Mounted saved startup/response revisions, no passive model start, exact explicit load and late navigation guard. |
| Models retains dirty values but takes the refreshed revision for Save, bypassing backend conflict detection. Independent review also reproduced validation/estimation using refreshed values while Save uses the retained draft. | Store the original saved base with active/stashed drafts; replace it only on explicit revert or confirmed Save. Derive preview, validation, estimates and Save from the same retained draft. | Concurrent save conflicts, stash/restore, successful Save plus failed refresh, copy, actual backend CAS, displayed/validated/submitted draft agreement. |
| Chat initial model read failure enables empty-workspace copy; independent later reads leave an unrelated aggregated startup error. | Independent cancellable read/retry/error ownership within Chat; only verified model catalogues permit empty copy; preserve action errors and user edits. | Mounted failures, independent recovery, reverse-order responses, inactive/unmount disposal and defaults recovery; actual native outage recovery. |
| Lab accepts a run then loses its observer/control identity when the immediate run read fails. | Retain accepted run identity before observation and retry observation independently. | Mounted accepted action plus failed read, correct Stop/disabled starts, later recovery without another start. |
| Browser initial GET overwrites newer streamed session state; attention responses overwrite newer counts/errors. | Order observations in each existing frontend owner. | Deferred GET versus actual SSE state/frame; reversed attention completions and disposal. |

## Risks / Trade-offs

- Cancellation races admission → prove lock ownership and keep pending cancellation while admission may still dispatch.
- Reservation release wakes recursively → notify only actual release and test bounded drain behaviour; use the existing coordinator.
- Read recovery overwrites edits or another owner → independent request generations, cancellation, exact draft/selection guards and mounted reversed completion tests.
- A model is currently in use in the product → native validation uses isolated data/processes, immutable installed weight paths and CPU inference; never reuse the older window as new-build evidence.
- Broad changes conceal unrelated work → disjoint implementation ownership, behaviour-focused commits, fresh-context review, final applicable gates and preserved later change directories.

## Migration Plan

Refresh local built artifacts and verify the exact processes exercised. Preserve the current user session when replacing it would disrupt live work; report any deployment limitation explicitly. A revert restores prior code without deleting product records or model weights.
